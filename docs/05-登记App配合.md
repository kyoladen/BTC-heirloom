# 05 · 与登记 App 配合

> 登记 App 在本方案中的定位：**本地加密的资产登记簿**，不是密码管理器。
> 它和树莓派、SeedSigner 一样，只是本方案要准备的工具之一。
> 获取：任意可信来源的本地加密登记工具均可；本方案只依赖其导出的 `.vault` 格式，不绑定具体产品。

## App 的设计边界

- 纯本地，AES-256 加密，数据不联网、不上传服务器
- **不记录完整密钥**：助记词、私钥、完整登录密码永不进 App
- **可记录不完整信息**：BIP39 口令（缺种子=乱码）、资产存放位置、取用步骤、恢复教程附件
- 可导出 `.vault` 加密备份文件，与密码分开保管

"不记密码"的准确表述是 **"不记录完整密钥，只记录不完整信息"** ——
这是密码学上可验证的边界，比字面口径更诚实。

## Vault 密码的要求

- 机器生成，14+ 位真随机（约 92 bit 熵），**人脑想的不算**
- 激光打印 + 过塑，纸质三处存放
- 写下即永不更换（如需更换，三处同步更新 + 重新分发 vault）

##.vault 格式的开放性要求（重要）

为保证"不依赖 App 存活"，`.vault` 必须满足：

1. 使用标准算法（AES-256-GCM 等认证加密 + 强 KDF，推荐 argon2id）
2. 格式文档化，**用 openssl 等标准工具可独立解密**
3. 密码只在用户脑中/纸上，开发者与服务器永远接触不到明文
4. 换机、App 下架、公司倒闭都不影响解密

## 在 App 中记录什么（示例结构）

- BTC
- 存放位置：钢板在家保险柜 / 银行保险箱 / 老家（具体位置描述）
- SeedQR 位置：____
- BIP39 口令：____（不完整因子）
- Vault 密码存放：亲属A / 亲属B / 律师（位置）
- 附件：恢复教程 PDF（含测试钱包截图）、身后流程手册
- 第一步先联系谁、先办什么
- 交易所账户恢复码（注意：交易所继承另需走官方流程+KYC）

## 版本管理

- 每次钱包变动 → 重新导出 → 分发家人 → 以时间戳验新 → 旧版删除确认
- Vault 密码本身争取永不更换，把更新复杂度从 O(N×3) 降到 O(N)
