# 03 · 威胁模型

> 先定义敌人，再谈安全。世上不存在 100% 安全，只有管理好的 trade-off。

## 信任假设（必须为真的前提）

1. BIP39 / SHA256 / AES-256 在可预见未来不被攻破
2. 至少一处种子存放点 + 一处密码存放点不被同时攻破
3. 家人不主动串谋盗窃（诚信假设，见下）
4. 你本人每年做一次恢复演练（对抗遗忘与腐烂）

## 攻击者画像

| 攻击者 | 能力 | 本方案对其是否有效 |
|---|---|---|
| 入室盗窃 | 撬开一处保险柜/保险箱 | ✅ 有效：单处只有种子**或**只有密码，凑不出完整钱包 |
| 黑客（远程） | 钓鱼、恶意软件、供应链投毒 | ✅ 有效：种子永不触网；软件均校验签名后安装 |
| 内鬼家人 | 有 vault 文件，知道全部流程 | ⚠️ 诚信假设：技术上可独立解密，需配合正式遗嘱约束 |
| $5 扳手（胁迫） | 物理胁迫你本人 | ⚠️ 任何自保管方案的共有弱点；"持有 BTC"本身的保密是最好的防御 |
| 时间 | 遗忘、腐烂、搬家、去世 | ✅ 有效：三地冗余 + 年度演练 + 时间戳版本管理 |
| 厂商/政府 | App 下架、公司倒闭、政策变化 | ✅ 有效：恢复只依赖开放标准（BIP39），不依赖任何厂商存活 |

## 单点清单（逐项已处理）

- [x] 种子单点 → 钢板三处存放（家/银行/老家）
- [x] 密码单点 → Vault 密码纸质三处（亲属A/亲属B·盲存/律师），避开有种子的地点
- [x] 文件单点 → Vault 文件 N+2 份（家人手机 + 银行律师兜底 + 亲属盲备份），带时间戳
- [x] 口令单点（遗忘）→ 年度演练强化记忆；**这是唯一无解的单点，已接受**
- [x] 共置单点 → **铁律：单一地点永不同时出现种子材料和 Vault 密码**
- [x] 软件单点 → 恢复不依赖特定软件，任意 BIP39 钱包均可
- [x] 人单点（执行人）→ 不设人类签名者；多签异地（给人）已明确拒绝

## 已知弱点（诚实列出）

1. **内部人风险**：家人凑齐文件+密码可独立行动。这是诚信假设，需用正式遗嘱约束，技术无解。
2. **口令遗忘**：BIP39 口令只在脑子里，失忆/长期不演练=丢币。无解，只能管理。
3. **$5 扳手**：所有自保管方案的共有弱点。缓解：尽量少让人知道你持有 BTC。
4. **灰色地带**（植物人/失踪/失忆）：无死亡证明但失去行为能力时，家人技术上可提前解密动用。这是 bug 还是 feature（应急医疗费），需在设计时决定并写进教程首页。
5. **银行慢路径**：保险箱开启走继承公证，耗时以月计。定位为兜底，不指望应急。

## 设计原则

1. **不完整信息原则**：只记录不完整密钥。BIP39 口令可记（缺种子=乱码）；
   助记词、私钥、完整登录密码永不进任何数字记录。
2. **Kerckhoffs 原则**：安全不依赖保密。本方案公开后依然成立。
3. **分散地点，不分散控制权**：多签签名者不给任何人（人的意外与关系破裂是大概率事件）。
4. **生前无敌，身后必达**：生前任何单点攻不破；身后家人必有路径拿到。
